# Homelab

个人 Homelab 的建设记录与操作手册。目标是**任何一步都能照着重做**，而不是"当时好像是这么弄的"。

每份文档按 **是什么 → 为什么这么选 → 选错会怎样** 组织，并附实际踩过的坑。

---

## 仓库地图

| 目录 | 内容 | 性质 |
|---|---|---|
| **[`01-infrastructure/`](01-infrastructure/)** | 装 Proxmox → 网络规划 → 核心概念 → 虚拟机模板 | **地基**，只做一次 |
| **[`02-gateway/`](02-gateway/)** | 旁路由：出站分流 + 入站回家（mihomo）<br/>含[原理说明](02-gateway/principles.md)：策略组 / 规则 / TUN / fake-ip | **服务 ①** |
| **[`tools/`](tools/)** | 批量推送与执行（`fleet.sh`） | 横向工具，不编号 |

**编号语义**：`01` 是地基，后续所有服务都建在它产出的模板之上；`02+` 是服务，各自独立、可增删。

**从零开始**：`01-infrastructure/` → 得到一台可克隆的模板 → 每个服务目录从模板克隆一台机器。

## 硬件

### `pve`（旧节点，常开）

| 部件 | 型号 | 备注 |
|---|---|---|
| CPU | Intel i7-12700F | 12C/20T（8P+4E），**F 后缀无核显** |
| 主板 | 华硕 TUF GAMING B660M-PLUS D4 | BIOS 1402 (2022-04)，4 DIMM |
| 内存 | DDR4-3200 32 GB | 实测满频 |
| 系统盘 | 铠侠 RC20 1TB NVMe | **无 DRAM 缓存**（影响文件系统选型） |
| 显卡 | 耕升 GTX 1050 Ti 4GB | Maxwell，带 UEFI GOP |
| 网卡 | 板载 Realtek 2.5G | Proxmox 无 Wi-Fi 支持，必须有线 |

> 机器自身的 hostname 是 `pve`。早期文档用过 `pve-old`，已统一为 `pve` —— PVE 节点名嵌在 `/etc/pve/nodes/<name>/` 目录结构里，改名要连 VM 配置一起搬，风险大于收益。

### Mac mini（常开）

管理终端 + **救援通道**。不承担网络转发角色，宿主机故障时仍可独立上网排查。Wi-Fi 已关，只走有线。

## 网络速查

```
网段     192.168.5.0/24
主路由   192.168.5.1        中兴光猫（zte.home）
DHCP 池  192.168.5.100-199
```

| 段 | 用途 |
|---|---|
| `.2 - .7` | 网络基础设施（物理或虚拟）。`.2` = `vm-router` 旁路由 |
| `.8 - .9` | Mac mini（`.9` 有线） |
| `.10 - .19` | Proxmox 宿主机与其他物理机。`.10` = `pve`，`.11` = `pve-x99`（规划中） |
| `.20 - .39` | 旧节点上的 VM / LXC —— **实验性，可重建** |
| `.40 - .59` | 新节点上的 VM / LXC —— **实验性，可重建** |
| `.60 - .69` | **家庭长期服务** —— 地址会被写进电视和手机，不能随便改，且不绑宿主机 |
| `.90 - .99` | 练手 / 临时机，用完即删 |
| `.240 - .250` | k8s LoadBalancer 预留 |

完整分配表与选型依据见 [01 · 网络规划](01-infrastructure/02-network.md)。

### 常用入口

| 服务 | 地址 |
|---|---|
| Proxmox Web | `https://pve:8006`（用户 `root`，Realm 选 Linux PAM） |
| SSH | `ssh pve` / `ssh vm-router` |
| 光猫管理页 | `http://zte.home` |

> 名字能直接用，是因为 Mac 上配了 `/etc/hosts` + `~/.ssh/config`。**写进 `/etc/hosts` 的名字优先级高于 DNS，不会被代理的 fake-ip 接管**。

## 文档约定

| 约定 | 说明 |
|---|---|
| **图一律 Mermaid** | 源码内嵌在 Markdown，用 `mmdc` 渲染校验通过才算完成 |
| **每个配置项说明"为什么"** | 而不只是"填什么"；并说明选错会怎样 |
| **坑单独成节** | 标注现象、根因、解决方法，以及**判断是这个坑的关键信号** |
| **不可逆操作单独警示** | 用红点标记，且只标会导致故障的点 |
| **命令可直接复制执行** | 除占位符外不留手工填空 |

### 校验

```bash
npm i -g @mermaid-js/mermaid-cli
mmdc -i <文档>.md -o /tmp/out.md       # 渲染文档内所有 mermaid 块
shellcheck -S warning **/*.sh          # 脚本静态检查
```

## 机密管理

**任何机密都不进 git**，无论仓库公开还是私有。

| 类型 | 例子 | 处理 |
|---|---|---|
| 模板 / 结构 | `config.yaml.tmpl`、`*.env.example` | 提交 |
| **机密** | 节点地址密码、控制台 secret、订阅链接 | **只在 Mac 本地**，命名 `*.local.*`，权限 `600` |
| 可再生 | 渲染出的 `config.yaml`、规则集缓存 | 忽略 |

分发不走 git —— [`tools/fleet.sh`](tools/) 从 Mac rsync 推送，且**显式排除机密**；机密由各服务的部署脚本定向投递给需要的那一台。
